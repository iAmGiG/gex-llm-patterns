\subsection{Regime Criteria}
\label{sec:methods:criteria}

A 30-trading-day window is a persistent regime when three criteria hold \cite{regan2026regimes,regan2026jrfm}: (i)~persistence, at least 21 of the 30 days (70\%) share the sign of net GEX; (ii)~magnitude, the mean absolute net GEX is at least \$5~billion; and (iii)~stability, the sign changes at most five times. The classifier labels every other window as low conviction (persistent sign and mean magnitude of at least \$3~billion, but failing a criterion) or transitional. The detection label used throughout is the binary persistent or not-persistent verdict (\ident{regime_detected} for the model, \ident{clf_should_detect} for the classifier). The thresholds are those of the earlier studies and are not re-tuned.

\subsection{Daily GEX Series}
\label{sec:methods:series}

For each symbol and trading day $t$ the net dealer gamma exposure is
\begin{equation}
\mathrm{GEX}_t=\sum_{i\in\mathcal{C}_t} s_i\,\Gamma_i\,\mathrm{OI}_i\cdot 100\cdot S_t^{2}\cdot 0.01,
\qquad s_i=\begin{cases}+1 & \text{call,}\\ -1 & \text{put,}\end{cases}
\label{eq:gex}
\end{equation}
where $\mathcal{C}_t$ is the set of contracts listed on day $t$ with a defined gamma $\Gamma_i$, positive open interest $\mathrm{OI}_i$ and a positive underlying price $S_t$. The series of Table~\ref{tab:series} differ in how $\Gamma_i$ is obtained, in which expiries and legs enter $\mathcal{C}_t$, and in where the values come from.

\subsection{Provenance of the Published Inputs: Put-Row Loss, Reload and Rebuild}
\label{sec:methods:lineage}

The published inputs cannot be regenerated from today's database. The raw options table was reloaded on 2026-02-03, one month after the Phase 4A run, and an upstream defect of the earlier load (option type defaulting to call) had removed the put rows of the raw table for the dates from about October 2023 to December 2025. The exact inputs were therefore recovered from the surviving Phase 4A batch file (Section~\ref{sec:results:inputs}); the inputs of the Phase 3 and 4 baseline runs of November 2025 survive in the same way. Eight dated events fix the lineage:
\begin{itemize}
\item 2025-11-20: the Phase 3 (2024) and Phase 4 (2020) baseline batches are run on o4-mini with calendar dates as day labels, 223 windows each (Section~\ref{sec:methods:arms}).
\item 2026-01-04: Phase 4A batch run (o4-mini-2025-04-16) on 1{,}476 SPY windows with ends from 2020-02-13 to 2025-12-31.
\item 2026-01-15: the pre-rebuild daily table is computed from the same raw table with Black--Scholes gamma and same-day expiries zeroed.
\item 2026-02-03: the raw options table is reloaded, with the put rows restored.
\item 2026-09-14: the model object gpt-6-luna is created.
\item 2026-10-04: the pre-rebuild daily table is archived and treated as read-only.
\item 2026-10-08: the daily summary is rebuilt from stored per-contract gamma, same-day expiries included.
\item 2026-10-12: equity options move from Alpha Vantage to Cboe delayed quotes, so every window ends on or before 2026-10-09.
\end{itemize}

\subsection{Windows and Deterministic Classifier}
\label{sec:methods:windows}

A window consists of 30 consecutive rows of a series (days $T{-}29$ to $T{+}0$), with one window per end date (stride one) and end dates up to 2026-10-09. A span that covers a calendar gap of more than four days is flagged (a gap of five or more days is not a holiday weekend), and the number of trading days of the symbol's master calendar (\path{gex.options_daily_summary}) that are absent from the series inside the span is stored with the window; a gap flags a window but does not drop it. Values are relabelled ``Day T-29'' to ``Day T+0'' with no dates or tickers, exactly as in Phase 4A, except in the two dated arms of Section~\ref{sec:methods:arms}, which carry the ISO dates of the November 2025 prompts. The deterministic classifier of Section~\ref{sec:methods:criteria} labels every window independently of any model call, and its verdict is the reference label for each arm. The windows that end in 2026, up to 2026-10-09, form the post-publication period (Section~\ref{sec:results:post}): the published sample ends on 2025-12-31, so the 29 earliest of these windows still contain days of it, and those with ends from 2026-02-13 lie entirely after it.

\subsection{Model Protocol}
\label{sec:methods:model}

All model calls use OpenAI's \ident{gpt-6-luna} through the Batch API (\path{/v1/chat/completions}, 24-hour completion window) in chunks of at most 1{,}500 requests. The model replaces the retired o4-mini; its API alias carries no dated snapshot, so the creation timestamp of the model object (2026-09-14) and the response identifier of every answer are stored. Requests use \ident{reasoning_effort} = \ident{medium}, the effort at which o4-mini ran in the published run, and the prompt text is unchanged from the Phase 4A run (prompt version \ident{v2.0_postgresql}); only the two dated arms of Section~\ref{sec:methods:arms} differ in the data lines, whose day labels are ISO dates. The answer has nine fields (Appendix~\ref{app:prompt}). The one protocol change is that these fields are enforced with a strict JSON schema, whereas the earlier runs requested JSON in the prompt text only; the change is disclosed here and does not alter the question asked. An answer is read as JSON; a second attempt tolerates raw control characters inside strings (one Phase 4A answer needed it), a last fallback extracts the JSON object from free text, and the parse status of every answer is stored.

\subsection{Experimental Arms}
\label{sec:methods:arms}

Table~\ref{tab:arms} lists the arms. The arm \ident{r1_o4mini} holds the published o4-mini answers, backfilled from the surviving Phase 4A output file without an API call; 64 of its 1{,}476 answers were lost to a parsing error in January 2026 and are re-parsed from the stored raw output. Every headline number uses the 1{,}412 answers of the published result; the 64 re-parsed answers are reported separately (as \ident{r1_o4mini_all}). The arms \ident{r1_p3_o4mini} and \ident{r1_p4_o4mini} are backfilled in the same way from the 223 stored answers of each November 2025 baseline run. The arm \ident{bridge_jan} sends the exact published inputs to gpt-6-luna, which separates the effect of the model from the effect of the inputs. The other arms run gpt-6-luna on the corrected series of each symbol; the ex-0DTE arms of QQQ and IWM start in 2020. The intraday arm uses composite windows whose last day is the late-session snapshot.

Two further groups of arms test the earlier results more directly. The Phase 3 (2024) and Phase 4 (2020) baselines of the earlier studies \cite{regan2026regimes,regan2026jrfm}, the 81.2\% versus 12.1\% contrast, were run on o4-mini in November 2025 with ISO calendar dates as day labels instead of relative labels. The arms \ident{p34_dated_2024} and \ident{p34_dated_2020} send the same 252 values per year, with the dates that were actually sent, to gpt-6-luna; the arms \ident{p34_obf_2024} and \ident{p34_obf_2020} send the identical values with Day-T labels. Within a year the two arms differ in the labels only, which isolates the effect of visible dates, and each is compared with the stored o4-mini answers. The two baselines are not on one convention (Table~\ref{tab:series}): the 2024 series is a gross call-plus-put magnitude with a negative sign imposed and the 2020 series is a magnitude without sign. We keep them verbatim because the aim is to replay the published contrast, which therefore cannot be read as one between a negative and a positive regime.

With the thresholds fixed in dollars, QQQ and IWM have no persistent window (Section~\ref{sec:results:cross}), so the unscaled arms only test whether the model also rejects every window. As a disclosed protocol change, the arms \ident{full_qqq_scaled} and \ident{full_iwm_scaled} therefore run on \ident{new_full_scaled}: the \ident{new_full} values of QQQ and IWM multiplied by one fixed factor per symbol, the median over 2020-01-01 to 2026-10-09 of SPY's open-interest notional divided by the symbol's (Appendix~\ref{app:series}). The factors are \tbd{} for QQQ and \tbd{} for IWM (over \tbd{} days), and they are stored with the series. Prompt, thresholds and classifier are unchanged, so scaled and unscaled arms are labelled by the same rule and run side by side.

Until the schema has been approved, the tables exist as parquet files under \path{data/backups/gex_llm/tables/} only; after approval the same tables are created, as standalone tables without foreign keys into the core tables, in the \ident{backups} schema of the project database \tbd{} (state which copy is authoritative, and that the schema is loaded, before submission). \subsection{Statistics}
\label{sec:methods:statistics}

Detection rates are reported with 95\% Wilson intervals \cite{brown2001interval}. Windows have stride one, so neighbouring windows share 29 of their 30 days and cannot be treated as independent. Every p-value is therefore accompanied by (i)~a calendar-quarter block bootstrap with 2{,}000 draws (seed 261) and (ii)~the same statistic on a non-overlapping 30-day subsample, the greedy chain of windows that share no day, starting at the first window of the period. Agreement between models is measured with Cohen's kappa, and paired detection rates across series or arms with the exact McNemar test (on the subsample; the stride-one value is reported as anti-conservative); effect sizes between years use $\varphi$.
