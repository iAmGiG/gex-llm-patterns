\section{Schema Field Order}
\label{app:schema}

The answer is constrained by a strict JSON schema with nine required fields: \ident{regime_detected} (boolean), \ident{regime_type} (one of four strings), \ident{positive_days}, \ident{negative_days}, \ident{sign_flips} and \ident{confidence} (integers), \ident{avg_magnitude_billions} and \ident{persistence_pct} (numbers) and \ident{reasoning} (string). The prompt and the complete schema are those of Paper A (Section~S6 of the Supplementary Materials of the companion manuscript \cite{regan2026rerun}) and of the stored requests; the deposit holds every request. vLLM decodes the fields in the order of the schema. The runs of this paper use two orders.

% The full run of D-33 uses the exploratory order (common.REASONING_FIRST_ORDER; run_metadata.local.schema_property_order of the llamarf_ runs).
\begin{itemize}[leftmargin=*,labelsep=5.5mm]
\item \textbf{Verdict first} (all stored arms): \ident{regime_detected}, \ident{regime_type}, \ident{positive_days}, \ident{negative_days}, \ident{avg_magnitude_billions}, \ident{sign_flips}, \ident{persistence_pct}, \ident{confidence}, \ident{reasoning}.
\item \textbf{Reasoning first} (the exploratory run of 40 windows and the full run of decision D-33, arms \ident{llamarf_*}): \ident{reasoning}, \ident{positive_days}, \ident{negative_days}, \ident{avg_magnitude_billions}, \ident{sign_flips}, \ident{persistence_pct}, \ident{regime_type}, \ident{regime_detected}, \ident{confidence}.
\end{itemize}

For gpt-oss-20b and Qwen3-8B the reasoning channel of the model ends before the JSON object starts (the reasoning parsers of vLLM separate it), so these models have reasoned before they write any field, whatever the order of the schema.
