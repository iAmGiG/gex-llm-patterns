% src: exploratory_llama_reorder_20261108/output.jsonl (local, git-ignored, kept with the deposit: 40 answers, regime_detected true in 32, equal to clf_should_detect in 26; completion tokens 150 on average; confusion table with clf_should_detect: 7 and 13 for the 20 rejected windows, 1 and 19 for the 20 detected ones); condensed/detections.csv.gz arm=pilot_llama_bridge_jan (40 answers on the same 40 windows: regime_detected true in 40, equal to clf_should_detect in 20); condensed/windows.csv.gz series_key=jan2026_phase4a clf_should_detect (20 of the 40 windows); planning/02_decisions_log.md D-30 (exploratory run, pilot), D-33
One run before the arms of Section~\ref{sec:results:llama} bears on this question. On 2026-11-08, after the 40-window pilot, we sent the same 40 requests to Llama~3.1~8B with the schema reordered so that the reasoning and the counts come before the verdict (Appendix~\ref{app:schema}). The run is outside the stored arms: it was a single exploratory pass, and its answers are kept with the deposit and not in the result tables. The 40 windows are balanced on the rule (20 detected, 20 not). With the verdict first the model detected all 40 and agreed with the rule in 20; with the reasoning first it detected 32 and agreed with the rule in 26. The order therefore changed the verdicts and moved them towards the rule, but not far: 13 of the 20 windows that the rule rejects were still detected, and 1 of the 20 that it detects was missed.
