\section{Methods}
\label{sec:methods}

\subsection{Setting Carried Over from the Earlier Work}
\label{sec:methods:setting}

The series, the windows, the rule and the prompt are those of the earlier publications \cite{regan2025obfuscation,regan2026regimes,regan2026jrfm} and of Paper A \cite{regan2026rerun}, which defines them and documents their lineage. In brief: a daily net GEX series of SPY is cut into windows of 30 trading days at stride one; the values are relabelled ``Day T$-$29'' to ``Day T+0'', so that no date or ticker is shown; and a window is a persistent regime when at least 21 of the 30 days (70\%) share the sign of net GEX, the mean absolute net GEX is at least \$5~billion and the sign changes at most five times. The deterministic rule labels every window, and its verdict is the reference label. The prompt states these criteria and asks for a verdict and the numbers behind it. It is byte-pinned: this paper rebuilds no request but reads the stored batch inputs of Paper A, so that every model receives exactly the text that the hosted models received.

\subsection{Requests}
\label{sec:methods:requests}

% src: scripts/validation/electronics/common.py chat_body, LOCAL_SPECS, MAX_COMPLETION_TOKENS=4000, RETRY_MAX_COMPLETION_TOKENS=8000; planning/02_decisions_log.md D-29 (request body of gpt-6-luna unchanged except the model name); runs.csv.gz max_completion_tokens, reasoning_effort, response_format
Each request is the request body of the hosted model of Paper A with the model name changed: one user message (the prompt with the 30 data lines of the window), a strict JSON schema as response format, \ident{reasoning_effort} = \ident{medium} where the model has a reasoning mode, and a limit of 4{,}000 completion tokens, reasoning tokens included. No temperature, top-p, top-k or seed is sent. An answer that ends at the limit is requested again once, at 8{,}000 tokens, and a window whose answer does not finish at 8{,}000 is unanswered. Llama~3.1 has no reasoning mode, so its body carries no \ident{reasoning_effort}; the chat template of Qwen3 does not use it, and the field is sent anyway. Answers are read as JSON, with a tolerant second attempt and a last fallback that extracts the object from free text, and the parse status of each answer is stored.

\subsection{Schema and the Order of the Fields}
\label{sec:methods:schema}

% src: scripts/validation/electronics/common.py REGIME_JSON_SCHEMA (property order regime_detected, regime_type, positive_days, negative_days, avg_magnitude_billions, sign_flips, persistence_pct, confidence, reasoning); exploratory_llama_reorder_20261108/input.jsonl (local, git-ignored; order reasoning, positive_days, negative_days, avg_magnitude_billions, sign_flips, persistence_pct, regime_type, regime_detected, confidence); 02_decisions_log.md D-30
The answer has nine fields (Appendix~\ref{app:schema}). In the stored schema the boolean verdict \ident{regime_detected} is the first property and the free-text \ident{reasoning} is the last. vLLM applies the schema by constrained decoding, and the model writes the fields in the order of the schema. For a model with a reasoning phase (gpt-oss-20b, Qwen3-8B) the reasoning channel ends before the JSON object starts, so the model has reasoned before it writes the verdict whatever the field order; the schema is applied once that phase has ended. A model without a reasoning phase (Llama~3.1~8B) writes the verdict first and the reasoning field last, so it commits to a verdict before any working appears in its output. A second order, with the reasoning and the counts before the verdict, is used in the exploratory run and in the full run of Section~\ref{sec:results:order}.

\subsection{Sampling and Seed}
\label{sec:methods:sampling}

% src: planning/02_decisions_log.md D-29 (no temperature sent; engine seed 261), D-30 (Hugging Face generation_config.json of meta-llama/Llama-3.1-8B-Instruct: do_sample true, temperature 0.6, top-p 0.9; read 2026-11-08), D-32 (Qwen/Qwen3-8B: temperature 0.6, top-p 0.95, top-k 20); local_<k>.log of the runs (vLLM line that the default sampling parameters were overridden by the model's generation config; in the git-ignored run folders data/backups/gex_llm/<run_id>/)
The requests send no sampling parameter, so vLLM samples with the defaults that the model repository carries in \ident{generation_config.json}: temperature 0.6 and top-p 0.9 for Llama~3.1~8B, temperature 0.6, top-p 0.95 and top-k 20 for Qwen3-8B, and for gpt-oss-20b, whose configuration sets no temperature, the engine default of 1.0 without top-p or top-k. The engine seed is 261 for all runs. These values are visible in the vLLM log of each run; they are not stored in the run metadata of the runs of the three models, and we read them from the repository files and the logs. The variants of Section~\ref{sec:methods:variants} do record what they send. For the three models this is a limitation (Section~\ref{sec:discussion:limits}). Because requests share the engine in batches whose composition varies, a fixed seed does not make the answers repeat exactly.

\subsection{Arms}
\label{sec:methods:arms}

% src: common.py ARMS (bridge_jan, full_spy, ex0dte_spy, p34_obf_2024, p34_dated_2024, p34_obf_2020, p34_dated_2020 and their oss_, llama_, qwen_ twins); results/detection_by_year.csv scope=all n_windows (1,476; 4,691; 4,691; 223 x 4); runs.csv.gz n_requests per arm (first pass, no retry run, no pilot) from condensed/runs.csv.gz
Each model answers seven arms, the twins of seven arms of Paper A, with the same series, windows and request text (Table~\ref{tab:results} lists them with their windows). \ident{bridge_jan} is the 1{,}476 windows of the published run; \ident{full_spy} and \ident{ex0dte_spy} are the complete SPY series of Paper A with and without same-day expiries, 4{,}691 windows each; the four baseline arms are the 2024 and 2020 samples of 223 windows that earlier papers compared \cite{regan2026regimes}, each with relative day labels (\ident{p34_obf_*}) and with the ISO dates that earlier prompts carried (\ident{p34_dated_*}). Within a year the two arms differ in the labels only. The arms of the models carry the prefixes \ident{oss_}, \ident{llama_} and \ident{qwen_}. Each model also answered a pilot of 40 windows of \ident{bridge_jan}, balanced on the label of the rule, which is not part of any rate; the first-pass requests per arm are in Tables~S1--S3. The variants of Section~\ref{sec:methods:variants} add the prefixes \ident{llamarf_}, \ident{osst0_} and \ident{llamat0_}.


\subsection{Repeats and Reference Columns}
\label{sec:methods:repeats}

% src: planning/02_decisions_log.md D-09 (REPEAT_FRACTION 0.05: 74 = round(0.05 x 1,476)), D-29 (six extra repeats of oss_ex0dte_spy); bridge_agreement.csv comparison=test_retest scope=all
A sample of 5\% of the windows of each arm (74 of the 1{,}476 windows of \ident{bridge_jan}) is sent a second time, in the same job as the first request, and the first and second verdicts are compared (test-retest). Because both requests share one engine run, the repeats measure variation within a job, not drift over time. Two reference columns of the tables are not results of this paper: the rule and the hosted successor gpt-6-luna, both from Paper A and labelled as such; the stored answers of o4-mini are the reference for the published windows.

\label{sec:methods:variants}

Three further local runs vary one setting each, on the same revisions, engine, seed and request text as the arms above, and carry their own model labels so that they never mix with them. The first (decision D-33) repeats the seven arms of Llama~3.1~8B with the reasoning field first in the schema (label \ident{llama-3.1-8b-instruct-rf}, arms \ident{llamarf_*}; the field order is that of the exploratory run, Appendix~\ref{app:schema}), with the default sampling of Llama~3.1~8B and 5\% repeats. The second and third (D-34) are a decoding control on the published inputs: gpt-oss-20b and Llama~3.1~8B (verdict first) answer the arm \ident{bridge_jan} with \ident{temperature} = 0 in every request (labels \ident{gpt-oss-20b-t0} and \ident{llama-3.1-8b-instruct-t0}, arms \ident{osst0_bridge_jan} and \ident{llamat0_bridge_jan}), to compare with their default sampling. Each variant had a 40-window pilot. These runs record the sampling parameters that they send and the order of the schema properties in their run metadata; the runs of the three models above do not. Qwen3-8B was not part of the control. In the run of D-33 two chunks did not start at first because two workers had chosen the same GPU; they were run later without any change of request or setting.

\subsection{Statistics}
\label{sec:methods:statistics}

% src: Paper A Methods (statistics): Wilson intervals, calendar-quarter block bootstrap with seed 261, exact McNemar test, Cohen's kappa; results/stats.yaml meta (seed 261, n_boot 2000); unanswered_analyses.yaml parameters contested_sets.pivotal (days 1, billions 0.5, flips 1, flips_below 0); unanswered_contested_agreement.csv arm=full_spy stratum=contested (n_windows 521); stored_e1_contested.csv arm=full_spy period=all definition=pivotal (n_contested 521, contested_pct 11.106374); unanswered_agreement_variants.csv (the three counts of the unanswered windows)
Agreement between a model and the rule is the share of windows with the same verdict among the windows that the model answered, with Cohen's kappa \cite{cohen1960coefficient}. When one rater gives the same verdict on every window, kappa is zero whatever the agreement. Windows have stride one, so neighbouring windows share 29 of 30 days; we therefore draw no interval around an agreement. For the few contrasts that carry a p-value, we use the calendar-quarter block bootstrap \cite{kunsch1989jackknife} of Paper A (exactly enumerated up to ten quarters, otherwise 2{,}000 draws with seed 261) and, for paired verdicts, the exact McNemar test \cite{mcnemar1947note}, whose stride-one value is anti-conservative. A rate over the windows that a model left unanswered is not estimated: we report bounds, with the unanswered windows counted as not detected (lower bound) and as detected (upper bound). A model that leaves windows unanswered has three agreements with the rule: over the answered windows, with the unanswered windows counted as not detected, and with them counted as errors; we report all three. Where we speak of windows that the rule decides narrowly (contested windows), we mean one definition throughout: exactly one criterion lies within its margin of its threshold while the other two criteria pass. The margins are one day around the 21 days of persistence (20, 21 or 22 days), \$0.5~billion around the \$5~billion magnitude threshold, and one sign flip above the limit (five or six flips). On the complete series 521 of the 4{,}691 windows (11.1\%) are contested; Table~S10 gives the results for three other margin sets. Percent values are rounded to one decimal, kappa to three.
